## 1. How v2 decides, and why W5 / W6 / W7 / W10 happen
- Band: per recording, `[f_low, f_drop - 200 Hz]`, f_drop = steepest fall of that recording's median PSD (`detect/audio_front.py:38-50`). Window features (`detect/features.py:66-107`): peak_to_median, peak width, flatness, entropy, SK, occupied BW, peak persistence, `max_dev_from_obs_median_db` (window spectrum minus the recording's own per-bin median, `features.py:104-106`).
- v2 inputs (`eval/interference_v2.py:46-48`): 3 raw features, 3 `tz_` (z vs a per-SATELLITE template, `detect/interference_det.py:75`), `peak_rarity` (`:76-78`), 5 `d_` = feature minus its recording median (`:79-80`). Template scale floored at the between-station SD of clean medians (`eval/interference_v2.py:60-70`).
- Decision: HGB probability, raw alert at tau 0.99985, smoothed 3 of 5 at tau 0.99983 (`models/interference_v2/threshold.json`; `interference_det.py:93-99, 147-156`).
- **W5**: an interferer at SIR 20-30 dB moves peak_to_median by little; the between-station scale floor makes the `tz_` z-scores small and tau sits at 1 % pooled FPR -> recording-level Pd [20, 30) dB 0.04 (`eval/results.md`).
- **W6**: an interferer present in most windows is in the recording median, so every `d_` feature and `max_dev_from_obs_median_db` cancel; only `tz_` features remain, and their scale is the between-STATION spread. Decision 93: v2 noise TPR 0.35.
- **W7**: f_drop is per recording. On dev, TECHSAT 1B stations 6, 2173, 4460 have f_drop 11.07 kHz on one pass and ~18.6 kHz on the other (station SD 5121 Hz), so band and features change between passes of the same receiver; the band includes the roll-off above f_edge (~10.15 kHz); the line screen is capped at f_edge - 100 Hz (decision 96), so interference between f_edge and f_drop is screen-blind.
- **W10**: one template per satellite; a station's own normal spectrum (birdie, filter shape) looks anomalous at a fixed global tau (dev: station 4272 in the flag tier on 75 recordings, decision 97; v1 4011 12.2 %).

## 2. Template design
- **Main (spectral)**: for station s and satellite n, a fixed band B_sn = [f_low, median f_drop of the enrollment passes - 200 Hz] (fixes W7: one band per receiver). Window PSD (same Welch as `features.py`, 23.4 Hz bins), in dB, minus its band median (gain-invariant) = r_w(f). Template = per-bin median m(f) and spread sigma(f) = max(1.4826 MAD over all enrollment windows, 1 dB). About 1000 windows per pass, so sigma(f) is estimable from one pass.
- Window score T_w = max over f of the mean of (r_w(f) - m(f)) / sigma(f) over 3 adjacent bins (narrowband 20-200 Hz). It does not use the recording median, so a whole-pass line stays visible (W6), and sigma is the receiver's own spread, not the between-station one (W5, W10).
- Decision: T_w >= tau_T, then 3 of 5 (v2 values, not tuned). tau_T is ONE global value (not per station), set for <= 1 % window FPR on scored not-attacked windows (v2 rule). **v3 alert = v2 alert OR template alert**; v2 unchanged and is the fallback (section 3). No new learned model.
- Ablation, not gated: feature-space template (per-station median / MAD of the existing `windows.csv` features as `tz_`), cheap because no spectra are needed.

## 3. Enrollment protocol (decided, P2-17)
- Enrollment set of a scored pass p = the **up to 3 most recent passes of the same station and satellite with start strictly before p's start** that pass Phase 1 audio QC (`data/qc.py` audio checks: readable, 48 kHz, mono, |audio duration - schedule| <= 10 s). The set is defined chronologically, independent of where the files are: each pass is read from local data if present (`data/raw/`), else fetched. An earlier dev pass enters with its clean variant only.
- Fetched passes (`eval/s3_enroll_fetch.py`): public SatNOGS Network API, same client (`data/satnogs_api.py`, 1 request / 3 s, cached), status `good`, same transmitters as Phase 1, start before 2026-11-01T00:00:00Z (never in the Phase 2 held-out window), metadata + audio only, into `data/raw_enroll/<obs_id>/` with its own SHA-256 manifest (`data/raw/manifest.csv` is frozen); raw files never modified; enrollment only, **never scored**.
- k = number of enrollment passes found: target 3, minimum 1. Results reported by k (1, 2, 3). k = 0: v2 only, reported separately as `fallback`.
- Dev before fetching: 60 passes, 22 stations; 2107 / 4272 (FUNCUBE-1) 12 passes each, 16 TECHSAT 1B stations 2, 4 stations 1 (local-only k = 1 would leave 38 scored passes).
- Held-out: the same rule; for held-out passes the enrollment candidates are any earlier QC-passing passes (dev, fetched before 2026-11, or earlier November passes of the held-out set itself, which are then scored as well, since each is scored with its own earlier passes only). Written in the S3 gate addendum.

## 4. Evaluation on dev (LOSO, train + calib)
- Scored recordings: every variant of a dev pass with k >= 1: clean, benign, interference (random SIR), combo, replay / sequence audio as negatives (as v2). Windows with 0 < overlap_frac < 0.5 excluded (Phase L rule).
- **Dev SIR grid** (new, seed tag `s3-dev`): per train + calib clean recording, one narrowband interferer at SIR 0, 10, 20, 25, 30 dB, drawn by the Phase 1 recipe code (`data/make_recipes.py` `plan_interference` with fixed `snr_db`: tone or 20-200 Hz noise, f0 in the band, full pass with p 0.4), seed = `attacks.common.recipe_seed(obs_id, "s3-dev/snrgrid_<+dd>")`, applied with the same chain; recipes in `data/recipes_s3dev/` (`data/recipes/**` is frozen).
- For held-out station s: tau_T from the other 21 stations' scored not-attacked windows; station s is scored with its own chronological enrollment. v2 scores: station-out-of-fold scores reproduced with `eval/interference_v2.py` loso (6 GroupKFold folds, decision 92; the fold scheme differs from 22-fold LOSO, stated); v2 is scored on exactly the same recordings, SIR grid included.
- Gate (all on scored recordings, k >= 1 pooled; also by k, by satellite, Clopper-Pearson 95 %): (a) worst station window FA (after 3 of 5, clean + benign) <= 2 %; (b) **v3 alone** >= 0.55 of whole-pass interference variants (random-SIR `interference_*` variants whose segment is the whole recording, as the Phase 1 full-pass number) with >= 1 alert event; the line screen alone reported on the same recordings; whole-pass SIR-grid recordings reported, not gated; (c) SIR-grid recordings at 20, 25, 30 dB with >= 1 alert event > 0.04; 0 and 10 dB give the curve. Fallback (k = 0) recordings reported separately.

## 6. Risks and open questions
- Few passes: TECHSAT 1B results rest on ~16-34 scored passes; worst-station FA on one or two passes per station is noisy.
- Drift over 60 days (seasons, receiver changes, the f_drop flips of section 1): only the 3 most recent passes are used; report score vs enrollment age on 2107 / 4272.
- Poisoning: an interferer present in an enrollment pass is learned as normal. Stress test (reported, not gated): enroll the interference variant instead of clean.
- Fetched passes may fail audio QC or be missing; the fetch walks further back until 3 pass or the list ends.
- Combining by OR adds false alarms to v2; the 2 % worst-station gate must hold for the OR.
