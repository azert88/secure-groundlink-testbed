# S1 plan – replay detector v2 against near-copy replay (W1, decisions 79, 102)

Status: plan only, no code. Gate: S1 row of `docs/GATES_PHASE2.md` ((a) near-copy named `replay` >= 0.80 of attacked dev recordings; (b) frame FA <= 0.1 %; (c) dev not-accepted <= 13.6 %).

## 1. v1 and why near-copies escape
- Copy identity is the SHA-256 only: intra-pass groups by `sha256` (`detect/replay_det.py:161-164`), cross-pass via `store.lookup(norad, sha256, ...)` (`:232`, `detect/hash_store.py`). One changed byte (`attacks/replay.py:59-69`, outside the counter / marker / byte 0, `:45-56`) breaks both: no `intra_*`, no `cross_*`.
- The copy keeps its counter, so only `regress` is left. It needs `line["ok"]` (`replay_det.py:201`). In exact mode, hash-matched copies are excluded from the line fit (`far`, `:131-132`) and weigh 1 against 2 for singletons (`:88-89`). Near-copies are singletons: they are not excluded, weigh 2 and count in the singleton on-line fraction (`:97-100`). When they are a large share of the pass the fraction falls below `line_ok_min_frac` = 0.8 (`models/replay/params.json`), `ok` is False and regress and line attribution are both off (decision 102, e.g. 56 % on line).
- Batched timestamps (`timing_reliable` False): no usable line by design, so regress can never fire there.
- Phase O result (`eval/out/evasion_near_copy/report.md`, test): named 0 / 133, replay evidence `{}` on every near-copy, 63 / 133 accepted. The 0.455 "any alert" comes from other detectors (likely sequence `same_counter`, named `forged`; [UNVERIFIED], test runs are not re-read for diagnosis).
- Naming: only `intra_run` / `regress_run` give `replay`, and `cross_*` gives `replay_cross_pass` (`detect/naming.py:46-49`). `naming.py`, `replay_det.py` and `hash_store.py` are in `models/{replay,fusion}/lock.json`: v1 stays byte-identical.

## 2. Proposed v2 (`detect/replay_det_v2.py`, imports v1 helpers, does not modify them)
(a) **Robust counter-time line.** Fit the line on residuals as in v1, then look for a second cluster (`_clusters`, tol `line_tol_s`) whose frames have counters already covered by the dominant cluster (counter ranges overlap, residual shift = replay delta). The dominant line = the cluster with the larger counter span / earliest coverage, not the larger weight. `ok` is computed on the dominant cluster's singletons only, with the lower-counter off-line cluster excluded as "copies". A copy cluster of >= 2 frames that shares one shift -> `regress_run`. A guard against a pass with a genuine counter reset (two lines with disjoint counters) is part of the design and is tested.
(b) **Near-duplicate matching.** For each frame, compare it with earlier frames of the same pass, and with archived frames of the same satellite, of the same length. Hamming distance in bytes, with the counter field, byte 0 (FUNCUBE-1) and the marker (TECHSAT 1B) masked (`protected_bytes` logic, re-implemented in v2). A pair with d <= d_max (set on TRAIN, §3) is treated like a hash match: intra pairs go through the same original / copy attribution and shift runs (`:166-198`), giving `intra_run` / `intra_single`. Cross pairs go through the same concurrent-reception test (`:144-158`), giving `cross_run` / `cross_single`. The archive of bytes = a new `detect/frame_store_v2.py` (same content as the hash store plus raw bytes; 828 + 162 train frames, `params.json` `store_frames`).
(c) Score: unchanged rule, frame score = max over evidence kinds, same score levels. v2 emits **only existing kind names** so the locked naming and fusion rules apply unchanged; the reason text says "near-duplicate, d = k bytes". Exact matches keep d = 0 and behave as v1. τ re-calibrated on calib (target FPR 1 %), stored in `models/replay_v2/`.

## 3. Natural near-duplicate rates (TRAIN only)
New script `eval/s1_near_dup_rates.py`: on clean TRAIN frames, per satellite and per frame type (FUNCUBE-1 frame type, TECHSAT 1B beacon), the histogram of the minimum masked Hamming distance (i) within a pass, (ii) against earlier passes. Also the same for consecutive beacons (slowly changing telemetry is the main false-alarm risk). Rule: d_max = largest d with a natural rate <= 0.1 % of frames per satellite (frame FA budget (b)); if d_max < 1 for a satellite, near-dup evidence is disabled there and this is reported as a negative result. Output: `models/replay_v2/near_dup_rates.json`, plus a row in `docs/PROGRESS.md`.

## 4. LOSO validation (train + calib) and near-copy dev variants
- Dev variants: new `eval/s1_make_dev_variants.py` reads the frozen recipes of train + calib observations only (asserts the split from `data/splits.json`; refuses test and `data/holdout_p2/`). It applies them with `attacks.apply.apply_recipe` and then `near_copy` with seed `recipe_seed(obs_id, f"{variant_id}:s1_dev:{k}")`, a new tag distinct from Phase O. Paired exact controls are kept. Frames only, written to `out/s1_dev/`.
- LOSO: for each train + calib station s, fit d_max and the line parameters on train frames of the other stations, set τ on their calib, and score s: gate (a) recall named `replay` on near-copy, (b) frame FA on clean + benign, (c) not-accepted on clean + benign. Gate holds if it holds pooled AND the worst station is reported. Exact-copy recall must stay 1.0 (regression check, reported).
- Then: gate already in `GATES_PHASE2.md` -> LOSO -> `eval/lock.py` lock `replay_v2` (+ a `fusion_v2` that selects it in `detect/run.py`) -> single test run of `eval/evasion_near_copy_v2.py` (new file, same protocol as Phase O) reported next to v1.

- New: `detect/replay_det_v2.py`, `detect/frame_store_v2.py`, `eval/s1_near_dup_rates.py`, `eval/s1_make_dev_variants.py`, `eval/s1_loso.py`, `eval/evasion_near_copy_v2.py`, `tests/test_replay_det_v2.py`. Config: a `detectors.replay_v2` block; `detect/run.py` selection by version. Untouched: `replay_det.py`, `naming.py`, `hash_store.py`, `fusion.py`, recipes, splits.
- Tests: v2 == v1 on exact-copy fixtures; a 1-byte near-copy intra run gives `intra_run`; a cross near-copy gives `cross_run`; the robust line stays `ok` with 50 % copies; a counter reset is not flagged; masked bytes are ignored; batched timestamps + near-copy still caught via (b).
- Cost [UNVERIFIED estimates]: Hamming over about 30 frames per pass x <= 828 stored frames is negligible. The causal loop (`detect` re-scores every prefix, O(n^2)) dominates; it stays per-pass under 1 GB RAM, 1 worker. LOSO + dev variants: tens of minutes, resumable per observation, run by you.

## 6. Decisions (2026-11-20, user)
1. "Same counter, different bytes" IS replay evidence for v2, only if its natural rate on clean TRAIN frames is ~0 (measured by `eval/s1_natural_rates.py`, step 2).
2. Reuse the existing evidence / alert names if they can express it; otherwise a NEW file `detect/naming_v2.py`. Locked files are never edited.
3. Stress sweep: near-copies with 1, 2, 4, 8, 16 modified bytes (outside counter / marker fields), on the dev variants; reported as a curve, no gate.
4. Gate pooled over LOSO folds (near-copy named `replay` >= 0.80; replay frame FA <= 0.1 %; dev recordings not accepted <= 13.6 %); the worst station is always reported next to it.
