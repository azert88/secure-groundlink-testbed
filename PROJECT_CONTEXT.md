# Project context and design decisions (from planning sessions)

Read together with CLAUDE.md. This file records WHY we chose the design.

## Challenge facts (from official PDFs)
- Track 1 question: "Can a stored signal or sequence be authenticated?"
- Official reference data: SatNOGS Network Observations (or organizer-supplied telemetry).
- Standard test: replay a valid 5–20-frame subsequence, inject ONE sequence anomaly,
  add narrowband interference digitally at a hidden SNR. Jury supplies a held-out recording.
- Safety: files only for Phase 1 (no radiated attack). Hardware gives no scoring advantage.
- Phase 1 scoring (100): threat model 15, architecture & trust 15, signal processing 15,
  detector design & evaluation 20, standard scenario & evasion 20, feasibility 10, clarity 5.
- Phase 2 includes "held-out standard attack & evasion" (20 pts).
- Tie-break: held-out attack score, then LOWER FALSE-ALARM RATE.
- Must report: detection quality, false alarms, latency, memory, security overhead.
- Other public data may complement, but the standard scenario must use SatNOGS.

## Two lines of defence
A. Prevention (trust layer): ground station signs each frame on reception
   (session id, monotonic counter, timestamp, prev-hash, HMAC-SHA256) + Ed25519-signed
   manifests of data and model, pinned public key. Replay/injection/modification on a
   signed stream is detected deterministically. Measure overhead (us/verify, bytes/frame).
B. Detection on unsigned recordings (the jury's held-out file will not carry our signatures):
   content-based detectors below.

## Detectors
- Replay: SHA-256 per frame; search for RUNS of already-seen frames (length >= 2),
  intra- and inter-observation hash store. Learn the natural duplicate rate on clean
  passes first (some satellites legitimately repeat identical beacons).
  Audio level: segment similarity (spectrogram correlation) + splice discontinuities.
- Sequence: counter/uptime monotonicity, inter-arrival time vs beacon period (robust z),
  frame length and type, telemetry field profiles.
- Interference: 1 s windows, Welch PSD features; supervised HistGradientBoosting trained on
  synthetic injections (wide SNR / frequency / width / duration ranges) in TRAIN observations;
  isotonic calibration on CALIB observations; alert threshold set on clean CALIB data
  for ~1% false alarms (conformal-style quantile).
- Fusion: per frame/window decision (accept / flag / quarantine) + confidence + reason text.

## Training data policy
- Normal data (train split): learn normal profiles for all detectors.
- Synthetic attacks (generated by our scripts on train split only): train the interference
  classifier.
- Calib split: calibration and thresholds only. Test split: evaluation only.
- Benign conditions (gain change, weak pass edges, noise rise, fading, natural repeats)
  are labelled NOT attack and included in calib and test to measure false alarms.

## Evaluation protocol
- Splits by observation ID (also try held-out stations/satellites for generalization).
- Leave-one-attack-variant-out to mimic the jury's held-out test.
- Metrics: precision, recall, F1 per attack; FPR on clean AND on benign; Pd vs SNR curve
  and minimum detectable SNR; ECE + reliability diagram; latency (ms/frame, ms/window);
  peak memory; security overhead.
- Evasion: interference just below threshold, intermittent, overlapping the signal;
  cross-pass replay; plausible forged frame with consistent counter.

## Out of scope for Phase 1
Deep learning, RF fingerprinting (needs high-rate IQ, SatNOGS gives demodulated audio),
adversarial ML attacks, model quantization, hardware. Hardware (3 PlutoSDR + 2 Raspberry Pi,
coax only) is planned for Phase 2 demo, with a file-based replayable fallback.

## Open questions to organizers

- Is the replay applied to the signal or to the frame sequence?
